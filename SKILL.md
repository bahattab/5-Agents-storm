# 0 - 5 Agents storm

Apply the user's Storm methodology to the actual task, preserving its purpose, audience, language, tone and constraints. The outcome is a coherent synthesis, not five role reports. If the invocation contains no topic and context supplies none, ask only for the topic or task.

Privately assess the topic through five contrasting lenses: the practitioner tests feasibility, resources, tradeoffs and consequences in real conditions; the academic evaluates accessible evidence, methodology, causality and generalizability; the skeptic tests assumptions, counterexamples, missing information and failure conditions; the motive analyst considers incentives, interests, power and biases without inventing hidden intentions; the historian examines relevant precedents, recurring patterns and differences that weaken an analogy. These are analytical perspectives, not claims that five autonomous agents ran.

Weigh the strongest competing explanations against evidence, practical constraints and the user's objective. Resolve contradictions where support permits, identify the decisive tradeoff, and choose a defensible conclusion or action. Where uncertainty remains material, express it naturally in the synthesis and state what would change the conclusion. Decisiveness must not turn unknowns into facts or force false certainty.

Return the final deliverable directly as dynamic, connected prose. Do not enumerate the perspectives, reproduce a debate or votes, reveal private deliberation, use bullets or numbered lists, or impose recurring headings, fixed templates or role labels. Embed relevant evidence, citations, qualifications and recommendations smoothly in the text. Match depth to the task; avoid a theatrical preamble and filler. If the user explicitly requires code, a table, a checklist or another structured artifact, preserve that requested artifact and use flowing prose for the accompanying synthesis.

Use real, accessible sources when material claims require verification. Distinguish fact, inference and speculation in ordinary language; never fabricate sources, history, statistics, motives, tool results or consensus. If verification is unavailable, state the relevant limit concisely. Do not expose hidden chain-of-thought; if asked for justification, provide a brief conclusion-level explanation with evidence and key tradeoffs.

The portable core works in any agent that can read and follow Markdown instructions. No account, API key, package, browsing tool, orchestration framework or runtime installation is required. With a skill loader, install this folder in that host's skill directory and invoke its supported name or trigger phrase. Without a loader, read this SKILL.md or supply it as task instructions. Natural-language trigger detection depends on the host; it cannot be guaranteed by this file alone. Preserve higher-priority instructions and the user's existing authorization boundaries.

Use the five lenses within one agent by default. If the user explicitly requests actual separate agents and the host supports authorized delegation, assign all five perspectives with identical task and evidence constraints, in bounded batches if concurrency is limited, then synthesize their supported findings into one final answer. Do not simulate tool execution or claim independence when using a single agent. A host without delegation still supports the full core method. Optional delegation does not authorize external messages, paid calls or publication.

Before delivery, check that the conclusion addresses the task, survives the strongest relevant objection, reflects the evidence, includes material uncertainty, and reads as one integrated answer without mechanical role scaffolding. Keep this check private.
